# Contributing

Follow repository `CONTRIBUTING`, pull-request template, branch protection,
release policy, ownership rules, and CI requirements when present.

Default contribution flow:

1. Read project instructions and relevant architecture/docs before starting.
2. Confirm scope and existing decisions.
3. Match established code and test patterns.
4. Add or update tests for behavior changes.
5. Update user-facing and technical docs in same change when behavior or public
   contracts change.
6. Run applicable formatters, linters, builds, tests, and validation commands.
7. Keep each change reviewable and centered on one concern.
8. Describe intent, trade-offs, verification, and known follow-ups honestly.

Never fabricate command results, hide modified files, bypass required checks, or
mark work complete without evidence. Separate unrelated cleanup into follow-up
work unless needed for safe implementation.
