# Collaboration and review conduct

Keep engineering discussion direct, specific, and respectful.

- Critique code and outcomes, not people or presumed intent.
- Tie feedback to concrete evidence: file, line, behavior, failure mode, project
  rule, or reproducible example.
- Distinguish blocking defects, important improvements, optional suggestions,
  and questions. Do not present preference as correctness.
- Explain impact and, when useful, propose smallest viable fix.
- Acknowledge uncertainty and ask when repository intent is unclear.
- Avoid unrelated rewrites inside scoped changes. Track worthwhile follow-ups
  separately.
- Resolve architecture disagreements by documenting constraints, alternatives,
  trade-offs, and decision owner—not by silently overriding prior decisions.
- Preserve user control before posting public comments, changing review state,
  or expanding scope.

Follow repository `CODE_OF_CONDUCT.md`, review policy, and communication norms
when present; they override these defaults.
